# arowser UI i18n design

- Date: 2026-11-13 16:56
- Status: approved; native error-card clarification approved during implementation
- Scope: existing Chinese UI strings in Arowser.swift (24 distinct keys), build.sh, resources, docs

## Intent

Make the existing Chinese UI strings across menus, the quit dialog, find bar, error card and relative times follow the system language: English as the development/default language, Simplified Chinese shipped alongside, one `.strings` file per language so contributors can add more. Existing English menu labels stay unchanged to preserve the Chinese user's current experience.

## Approach (chosen)

`NSLocalizedString` with **English-literal keys** + a single `zh-Hans.lproj/Localizable.strings`. English (and any untranslated language) falls back to the key itself — no `en.lproj` needed. Adding a language requires a `<language>.lproj/Localizable.strings` table and a resource copy step in `build.sh`.

Alternatives rejected: hardcoding English only (abandons Chinese users and the maintainer's own daily UI; zh-CN README would contradict reality); semantic keys like `menu.quit` (more ceremony, no benefit at this size).

## Mechanics

- Helpers in Arowser.swift: `L(_ key: String) -> String` and `LF(_ key: String, _ args: CVarArg...) -> String` (String(format:)).
- Format-string keys carry the English plural-ish form, e.g. `"%d windows will close"`, `"%d min ago"`, `"No closed windows in the last %d hours"`.
- Find bar text is injected into the page user-script via Swift interpolation of JSON-encoded localized values (the JS reads constants like `NO_MATCH` injected at template build, then assigns text/attribute properties).
- The error card remains an AppKit overlay and calls `L()` directly: failed navigation has no running page scripts. This corrects the original design's assumption that the card was page-rendered; the user approved retaining the native implementation.
- `zh-Hans.lproj/Localizable.strings` lists every key with the current Chinese text (no visible-text change for Chinese users).
- `build.sh` copies `zh-Hans.lproj/` into `Contents/Resources/`; `CFBundleDevelopmentRegion` is already `en`.
- A Python consistency test (`tests/test_l10n.py`) extracts `L("…")`/`LF("…", …)` keys from Arowser.swift and asserts the zh-Hans table covers them all and parses — RED before implementation, GREEN after.

## Non-goals

- No String Catalogs / .xcstrings (needs Xcode tooling; repo builds with bare swiftc).
- No in-app language override; system language decides.
- Chinese source comments stay as-is (not user-visible).
